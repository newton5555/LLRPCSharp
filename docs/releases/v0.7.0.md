# LLRPCSharp 0.7.0 Release Notes

> Release Date: 2026-08-04

## 🌟 Highlights & Major Improvements

- **托管盘点入口收敛**:公开盘点入口统一为 `StartInventoryAsync(InventorySettings)`（一段式：部署并启动）与 `StartInventoryAsync()`（两段式：启动已部署）；无会话版 `StartAsync` 系列转为 internal（仅供内部 Tag Access 与连接级流程使用）。部署契约明确：带 Inventory 意图的部署会删除设备上全部 ROSpec/AccessSpec（LLRP id=0 语义，SDK 完全接管）。

- **SDK API 增强**:
  - `TagReport.EpcHex` 便捷属性 + `EpcBitLength`（保留非字节对齐 EPCData 的精确位长）。
  - `ImpinjTagReportExtensions.GetSerializedTidHex()`（Impinj Serialized TID 十六进制投影）。
  - `TagSelection` / `InventorySelectFilter` 的 `BitLength` 语义统一：`0` = 使用全部打包位（LLRP 位数组语义）。
  - 新增 `TagReportsDropped` 事件：连接级报告缓冲（DropOldest）满时通知，与设备端 `ReportBufferOverflow` 区分。

- **真机验收测试（新增 `LlrpSdk.Hardware.Tests` 10 用例）**:
  - 标准 LLRP 路径（Force101：连接/能力/defaults/配置/盘点，不启用厂商扩展）。
  - 托管一段式/两段式盘点、非破坏 Tag Access 读、Impinj SerializedTID 投影、配置查询。
  - 已在 Impinj R420 6.4.1.240（`192.168.41.134`）实机 10/10 通过；验收证据见 `docs/acceptance/reader-interoperability.md`。

- **Bug 修复**:
  - `AccessSpecId=0`（LLRP 语义“无关联 AccessSpec”）的报告此前被误拒出 `InventorySession` 报告流（连接级正常掩盖了问题），已修复路由谓词。
  - `StartInventoryAsync(settings)` 改为部署成功后再构造 `InventorySession`，保证 session 快照到真实的托管 ROSpec/AccessSpec 标识。
  - 真机测试基建：禁用 xUnit 并行（共享设备）、失败路径 `try/finally` 清理、修复 `appsettings.local.json` 天线默认值被 Binder 追加导致的重复。

- **文档**:
  - `AGENTS.md`：AI 文档导航顺序、双语文档约定、硬件验收证据记录流程。
  - SDK API 指南新增 4.1 盘点配置恢复模式（default / 本地文件 / 设备快照 / 断电重启）与 4.2 一段式 vs 两段式选择。
  - `status.md` 部署契约、`showcase` 入口描述、ADR 0005 修正。

## 📦 Package Version

- `LlrpSdk`: `0.7.0`
- Target Framework: `.NET 10.0` / `C# 14`
