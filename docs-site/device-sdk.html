02 / DEVICE & VIRTUAL SERVER SDK

通用的 LLRP 服务端与虚拟读写器仿真核

在物联网与 RFID 系统开发中，依赖物理读写器会导致 CI 流水线无法脱机运行、边界异常难以复现。LlrpDevice.* 系列包提供符合 LLRP 规范的通用设备端 TCP 服务端与确定性软件虚拟读写器，支持在自动化测试中启动临时 TCP 端点。它用于协议、生命周期和业务流程测试，不模拟真实 RF 波形。

模块组成与分工

Device SDK 采用高度解耦的分层设计，既可作为独立的仿真读写器运行，也可用于为真实硬件编写 LLRP 固件服务端：

LlrpDevice.Abstractions

定义设备端基础接口（ILlrpDevice、IInventoryExecution、硬件能力、状态与射频事件）。

LlrpDevice.Server

通用的 TCP 网络服务端，负责 LLRP 报文解包路由、ROSpec/AccessSpec 资源管理与 LLRP 状态机。

LlrpDevice.Virtual

虚拟读写器仿真核，模拟物理天线波束覆盖、标签可见性、动态 RSSI 抖动与 C1G2 存储区读写。

LlrpDevice.Virtual.Hosting

宿主生命周期门面（VirtualLlrpDeviceHost），组合 Server 与 Virtual Device，提供开箱即用的异步启停接口。

快速开始：在 xUnit 测试中嵌入虚拟读写器

无需任何物理设备，通过 VirtualLlrpDeviceHost 即可在集成测试中启动一个运行在临时端口（Ephemeral Port）上的完整 LLRP 服务端： 

using System.Net;
using LlrpDevice.Virtual.Hosting;
using LlrpSdk;
using Xunit;

public class InventoryIntegrationTests
{
    [Fact]
    public async Task Reader_Should_Read_Simulated_Tags()
    {
        // 1. 配置 Hosting-level 虚拟读写器（注入 2 个模拟标签）
        var hostOptions = new VirtualDeviceHostOptions
        {
            ListenAddress = IPAddress.Loopback,
            Port = 0, // 0 表示自动绑定空闲临时端口
            Inventory = new VirtualInventoryOptions
            {
                Tags =
                [
                    new VirtualInventoryTag
                    {
                        ElectronicProductCode = Convert.FromHexString("E28011910000000000000001"),
                        AntennaId = 1,
                        PeakRssi = -55
                    },
                    new VirtualInventoryTag
                    {
                        ElectronicProductCode = Convert.FromHexString("E28011910000000000000002"),
                        AntennaId = 2,
                        PeakRssi = -62
                    }
                ]
            }
        };

        // 2. 启动虚拟读写器服务
        await using IVirtualLlrpDeviceHost host = VirtualLlrpDeviceHost.Create(hostOptions);
        await host.StartAsync();

        // 3. 使用客户端 LlrpSdk 连接此虚拟读写器
        await using var reader = LlrpReader.CreateBuilder(IPAddress.Loopback.ToString())
            .WithPort(host.BoundPort)
            .Build();

        await reader.ConnectAsync();
        ReaderSettingsDefaults defaults = await reader.GetDefaultSettingsAsync();
        await reader.ApplySettingsAsync(defaults.Settings);

        // 4. 执行盘点并断言标签数据
        await using var session = await reader.StartInventoryAsync();
        var reportedEpcs = new List<string>();

        await foreach (TagReport tag in session.ReadReportsAsync())
        {
            reportedEpcs.Add(tag.EpcHex);
            if (reportedEpcs.Count >= 2) break;
        }

        // 5. 验证结果
        Assert.Contains("E28011910000000000000001", reportedEpcs);
        Assert.Contains("E28011910000000000000002", reportedEpcs);
    }
}
提示： VirtualLlrpDeviceHost 实现了 IAsyncDisposable，在测试退出或异常抛出时会自动平滑关闭 TCP 监听器并释放资源。

LlrpDevice.Server (通用协议服务端)

LlrpDeviceServer 是一个独立于具体硬件实现的通用 LLRP 协议引擎，负责遵循 EPCglobal LLRP 规范处理客户端连接：

  • 多版本消息分发：支持 LLRP 1.0.1、1.1 与 2.0 报文路由与版本协商。
  • 规范级资源注册表：内置 LlrpResourceRegistry，自动维护客户端通过 ADD_ROSPEC、ADD_ACCESSSPEC 注册的参数树与触发器。
  • 定时与周期心跳：支持客户端配置的 Keepalive 触发器（周期或事件驱动），自动发送 KEEPALIVE 帧并监听 KEEPALIVE_ACK。
  • TagReport 组装与流控：根据 ROSpec 中的 ROReportSpec（按单标签、按天线轮询结束、或按 ROSpec 结束）打包 RO_ACCESS_REPORT。
// 仅使用通用 Server 承接自定义后端实现
ILlrpDevice myCustomDevice = new MyHardwareDevice();
var serverOptions = new LlrpDeviceServerOptions
{
    ListenAddress = IPAddress.Any,
    Port = 5084,
    IdleTimeout = TimeSpan.FromMinutes(5),
    FrameAssemblyTimeout = TimeSpan.FromSeconds(30)
};

await using var server = new LlrpDeviceServer(myCustomDevice, serverOptions);
await server.StartAsync();
Console.WriteLine("LLRP 设备服务端已启动，等待客户端接入...");

LlrpDevice.Virtual 仿真核

VirtualLlrpDevice 提供了可重复的 RFID 软件行为模拟：

RF BEAM

天线与视野过滤

模拟每根天线的覆盖范围与盲区。只有天线与标签所在的天线 ID 匹配时才会触发盘存。

VARIANCE

RSSI 衰减与抖动

支持配置基准 RSSI、确定性随机种子和整数 dB 抖动，用于稳定复现业务边界；它不是物理 RF 仿真器。

MEMORY

C1G2 内存仿真

完整模拟 EPC、TID、User、Reserved 存储区，支持 Read/Write/Lock/Kill 指令的持久化变动。

using LlrpDevice.Virtual;

// 配置确定性软件仿真参数
var deviceOptions = new VirtualDeviceOptions
{
    RfSimulation = new VirtualRfSimulationOptions
    {
        Scenario = VirtualRfScenario.Noisy,
        RandomSeed = 2026,
        RssiJitterDb = 2 // 整数 ±2 dB 抖动
    },
    Tags =
    [
        new VirtualTagDefinition
        {
            ElectronicProductCode = Convert.FromHexString("E280119100000000000000A1"),
            Tid = Convert.FromHexString("E28011052000600123456789"),
            UserMemory = [0xCAFE, 0xBABE],
            AntennaId = 1,
            PeakRssi = -48,
            AccessPassword = 0x00000000
        }
    ]
};

内置能力 Profile

读写器的硬件能力表决定了其支持的天线数、功率表与 RF Mode。虚拟设备内置了主流能力预设：

Profile 标识符 对应硬件/标准 特性描述
llrp1.0.1_standard 标准 LLRP 1.0.1 读写器 4 天线，1-30 dBm 功率表，标准 Tari 与 Gen2 模式
impinj.r420.llrp-1.0.1 Impinj Speedway Revolution R420 4 天线，支持 Impinj 专属扩展、RF 相位与自适应模式
llrp1.1_standard 标准 LLRP 1.1 读写器 支持 LLRP 1.1 协议版本探查与新版配置字段

实现 ILlrpDevice 桥接真实硬件

如果你正在基于专有射频芯片（如 Indy R2000/E710）或自有串口协议开发读写器，可直接实现 ILlrpDevice 接口，由 LlrpDeviceServer 自动提供标准的 LLRP TCP 接口： 

public class MyRfChipDevice : ILlrpDevice
{
    public ReaderCapabilities Capabilities => ...; // 返回射频芯片能力表
    public ReaderStatus Status => ...;

    public Task<IInventoryExecution> StartInventoryAsync(
        InventoryExecutionParameters parameters, 
        CancellationToken cancellationToken)
    {
        // 驱动底层串口或 SPI 射频模块开始搜标
        // 并通过 execution.ReportTagAsync 推送实时标签
        return Task.FromResult<IInventoryExecution>(new MyExecutionChannel(parameters));
    }

    public Task<TagAccessOperationResult> ExecuteTagAccessAsync(
        TagAccessRequest request, 
        CancellationToken cancellationToken)
    {
        // 驱动底层芯片执行写入、加锁等操作
    }
}
