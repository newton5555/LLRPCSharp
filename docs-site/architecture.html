04 / SYSTEM ARCHITECTURE

高内聚的业务门面，开放可扩展的协议内核

LLRPCSharp 将底层字节流、LLRP 帧解包、多版本协议定义、状态机与高层业务 API 分层解耦。不仅对传统 LTK.NET 进行全面现代化重构，也为离线编解码、自动化测试和虚拟设备提供了统一坚实的技术底座。

从 LTK.NET 到 LlrpNet：协议层的现代化重构

传统的 LTK.NET (LLRP Tool Kit for .NET) 诞生于 .NET Framework 2.0/3.5 时代，是 LLRP 生态中广泛使用的开源实现。它开创了“机器可读 XML 定义生成强类型协议代码”的优秀范式；本节只比较两套代码库的设计取舍，不把未经基准测试的性能差异当作结论：

对比维度 传统 LTK.NET (Legacy) 现代 LlrpNet / LLRPCSharp
定义输入与生成 仅支持单一 XML (llrp-1x0-def.xml)，依赖旧版 XSLT 转换 双输入流水线：支持官方 LTK XML 与手写 YAML，生成不可变强类型模型与高性能 Codec
内存与 GC 分配 依赖 ArrayList / 装箱拆箱，频繁 byte[] 复制，高并发下 GC 停顿严重 在协议编解码路径使用 ReadOnlyMemory<byte>、Span<byte> 与 BinaryPrimitives，减少不必要的数据复制
异步并发模型 旧式 APM 模式 (BeginRead/EndRead) 或线程阻塞轮询，易死锁 原生 async/await、System.Threading.Channels、IAsyncEnumerable<TagReport> 异步流与背压控制
架构分层解耦 网络传输、XML 解析、协议实体、业务调用全部糅合在单体程序集 高度分层：LlrpNet.Core 传输核心、LlrpNet.Protocol.* 纯协议模型、LlrpSdk 业务门面、LlrpDevice.* 设备端仿真
多版本与厂商扩展 硬编码锁定在 LLRP 1.0.1，无法支持版本协商 严格隔离 1.0.1 / 1.1 / 2.0 命名空间，通过 ILlrpProtocolAdapter 运行时自适应协商，厂商扩展 (Impinj/Zebra) 模块化插件接入
上层业务抽象 无高层封装，开发者必须手工拼接数十层嵌套的 PARAM_* 参数树 提供 Octane 风格的 ReaderSettings 声明式意图与 InventorySession，自动编译为标准 ROSpec/AccessSpec
继承与兼容： LLRPCSharp 延续了定义驱动的强类型协议模型，底层支持通过 reader.Protocol 与 LlrpNet.Protocol 直接构造或反序列化原生消息。迁移项目仍需按具体消息、设备和版本进行验证；本页面不承诺未经基准测试的“100% 兼容”或固定吞吐倍数。

资源所有权与隔离边界

SDK 托管层使用专有的保留资源 ID，既保证自动管理的便捷性，又防止干扰其他系统：

MANAGED

SDK 托管资源

固定使用 ROSpec 14150 与 AccessSpec 14151，由托管 API 自动部署与收敛。

FOREIGN

外部/第三方资源

默认采用 PreserveForeign 策略完整保留，发生冲突时上报异常而非静默删除。

ATTACHED

已有 ROSpec 桥接

通过 StartExistingRoSpecAsync(id) 接入 SDK 报告流，会话停止时保留定义。

协议适配器边界 (Multi-Version Convention)

为了支持多版本 LLRP（1.0.1、1.1、2.0），协议层生成独立的强类型命名空间。高层 SDK 门面零依赖特定版本生成类型，所有跨版本转换由 ILlrpProtocolAdapter 承担。 

// 多版本显式别名约定（禁止裸 using 版本化命名空间）
using V101Parameters = LlrpNet.Protocol.Parameters.V1_0_1;
using V11Parameters = LlrpNet.Protocol.Parameters.V1_1;
using V20Parameters = LlrpNet.Protocol.Parameters.V2_0;

// 版本显式清晰，防止不同版本 LLRP 类型混淆
V101Parameters.ROSpec roSpec101 = new(roSpecID: 14150, priority: 0, ...);
V11Parameters.ROSpec roSpec11 = new(roSpecID: 14150, priority: 0, ...);

通用设备端 Server 与 Virtual Device

仓库内实现了可用于 CI 自动化与应用联调的确定性软件虚拟读写器框架，无需物理硬件即可覆盖协议和业务流程；它不是 RF 波形或物理环境模拟器：

  • LlrpDevice.Abstractions：设备端通用合同（ILlrpDevice、IInventoryExecution、硬件配置与事件）。
  • LlrpDevice.Server：通用的独立设备端 TCP 服务端，支持 1.0.1 / 1.1 / 2.0 报文分发、状态机、Keepalive、ROReportSpec 与 C1G2 模拟。
  • LlrpDevice.Virtual：确定性标签发生器、天线过滤、RSSI 抖动与多标签移动模拟。
  • LlrpDevice.Virtual.Hosting：供外部进程直接调用的 IVirtualDeviceHost 门面。
  • LlrpVirtualDevice.Cli：独立的虚拟设备命令行服务，内置交互 Shell 与预设 Profile。
提示： 虚拟设备支持 llrp1.0.1_standard 与 impinj.r420.llrp-1.0.1 软件 profile，可用于标准 LLRP 客户端的连接、资源和盘点联调；厂商高级功能仍以实际测试为准。

协议定义与代码生成管道

所有协议实体源于 definitions/ 下的规范定义（XML/YAML）。通过 LlrpNet.ProtocolGenerator 自动化生成不可变消息、参数、枚举与编解码器，禁止手工编辑 *.g.cs 生成代码，确保协议一致性。
