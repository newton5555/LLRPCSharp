04 / SYSTEM ARCHITECTURE

高内聚的业务门面，开放可扩展的协议内核

LLRPCSharp 将底层字节流、LLRP 帧解包、多版本协议定义、状态机与高层业务 API 分层解耦。不仅提供现代 C# 的简洁高层接口，也为离线编解码、自动化测试和虚拟设备提供了统一坚实的技术底座。

资源所有权与隔离边界

SDK 托管层使用专有的保留资源 ID，既保证自动管理的便捷性，又防止干扰其他系统：

MANAGED

SDK 托管资源

固定使用 ROSpec 14150 与 AccessSpec 14151，由托管 API 自动部署与收敛。

FOREIGN

外部/第三方资源

默认采用 PreserveForeign 策略完整保留，发生冲突时上报异常而非静默删除。

ATTACHED

已有 ROSpec 桥接

通过 StartExistingRoSpecAsync(id) 接入 SDK 报告流，会话停止时保留定义。

协议适配器边界 (Multi-Version Convention)

为了支持多版本 LLRP（1.0.1、1.1、2.0），协议层生成独立的强类型命名空间。高层 SDK 门面零依赖特定版本生成类型，所有跨版本转换由 ILlrpProtocolAdapter 承担。 

// 多版本显式别名约定（禁止裸 using 版本化命名空间）
using V101Parameters = LlrpNet.Protocol.Parameters.V1_0_1;
using V11Parameters = LlrpNet.Protocol.Parameters.V1_1;
using V20Parameters = LlrpNet.Protocol.Parameters.V2_0;

// 版本显式清晰，防止不同版本 LLRP 类型混淆
V101Parameters.ROSpec roSpec101 = new(roSpecID: 14150, priority: 0, ...);
V11Parameters.ROSpec roSpec11 = new(roSpecID: 14150, priority: 0, ...);

通用设备端 Server 与 Virtual Device

仓库内完整实现了生产级的虚拟读写器框架，无需物理硬件即可进行 CI 自动化与应用联调：

  • LlrpDevice.Abstractions：设备端通用合同（ILlrpDevice、IInventoryExecution、硬件配置与事件）。
  • LlrpDevice.Server：通用的独立设备端 TCP 服务端，支持 1.0.1 / 1.1 / 2.0 报文分发、状态机、Keepalive、ROReportSpec 与 C1G2 模拟。
  • LlrpDevice.Virtual：确定性标签发生器、天线过滤、RSSI 抖动与多标签移动模拟。
  • LlrpDevice.Virtual.Hosting：供外部进程直接调用的 IVirtualDeviceHost 门面。
  • LlrpVirtualDevice.Cli：独立的虚拟设备命令行服务，内置交互 Shell 与预设 Profile。
提示： 虚拟设备支持 llrp1.0.1_standard 与 impinj.r420.llrp-1.0.1 档案，可直接接受 Impinj ItemTest 等标准 LLRP 客户端连接。

协议定义与代码生成管道

所有协议实体源于 definitions/ 下的规范定义（XML/YAML）。通过 LlrpNet.ProtocolGenerator 自动化生成不可变消息、参数、枚举与编解码器，禁止手工编辑 *.g.cs 生成代码，确保协议一致性。
