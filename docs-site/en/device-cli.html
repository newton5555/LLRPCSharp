04 / VIRTUAL DEVICE CLI SERVER

Standalone virtual reader service

LlrpVirtualDevice.Cli starts a deterministic software LLRP TCP service without application code. Choose a protocol/profile preset, load JSON tag data and control the host lifecycle from an interactive shell. It is a software test endpoint, not a physical RF simulator.

Overview

No-code launch

Start a test reader on the default loopback address and port 5084.

Protocol presets

Standard 1.0.1, strict 1.0.1, 1.1, 2.0 and an Impinj R420-shaped profile are available.

Lifecycle shell

Inspect status, toggle logs and stop, start or restart the same host.

1. Run a service

The default service listens on 127.0.0.1:5084. Use a preset or an explicit port when needed.

# Default: standard LLRP 1.0.1 on 127.0.0.1:5084
dotnet run --project src/LlrpVirtualDevice.Cli -- run

# Impinj R420-shaped software profile
dotnet run --project src/LlrpVirtualDevice.Cli -- run --port 5084 --preset impinj.r420.basic

# Explicit LLRP 2.0 software profile
dotnet run --project src/LlrpVirtualDevice.Cli -- run --preset llrp.standard20.basic

2. Presets

These IDs select protocol and capability defaults for software tests; they are not claims about a physical RF environment.

Preset IDProtocolPurpose
llrp.standard101.basicLLRP 1.0.1Standard deterministic reporting baseline.
llrp.standard101.strictLLRP 1.0.1Strict standard inventory checks.
llrp.standard11.basicLLRP 1.1Explicit 1.1 negotiation and message path.
llrp.standard20.basicLLRP 2.0Current translated 2.0 device-profile baseline.
impinj.r420.basicImpinj-shaped / 1.0.1Software extension and reporting path.
dotnet run --project src/LlrpVirtualDevice.Cli -- presets

3. Interactive live shell

The shell controls the service lifecycle and event logging while the virtual reader is running.

dotnet run --project src/LlrpVirtualDevice.Cli -- live --preset llrp.standard101.basic

> server status
> logs on
> server restart
> server stop
> server start

4. JSON configuration

Schema 1 JSON can select a profile, protocol version, report cadence, deterministic RF scenario and tag list.

{
  "schemaVersion": 1,
  "presetId": "impinj.r420.basic",
  "capabilityProfileId": "impinj.r420.llrp-1.0.1",
  "protocolVersion": "1.0.1",
  "reportIntervalMilliseconds": 100,
  "reportCount": 0,
  "repeat": true,
  "rfScenario": "noisy",
  "randomSeed": 2026,
  "rssiJitterDb": 1,
  "tags": [
    {
      "epc": "E28011910000000000000001",
      "tid": "E28011052000600123456789",
      "peakRssi": -55,
      "antennaId": 1,
      "userMemory": [51966, 47806]
    },
    {
      "epc": "E28011910000000000000002",
      "peakRssi": -62,
      "antennaId": 2
    }
  ]
}
dotnet run --project src/LlrpVirtualDevice.Cli -- run --config ./my-virtual-reader.json

5. Validation and capabilities

dotnet run --project src/LlrpVirtualDevice.Cli -- validate --config ./my-virtual-reader.json
dotnet run --project src/LlrpVirtualDevice.Cli -- caps

6. Interoperability

The service provides a standard LLRP TCP connection and an inventory integration path. Advanced vendor behavior and true-device interoperability still require target-specific validation.

  • Impinj ItemTest: the R420-shaped profile has connection and inventory integration evidence; other features need separate verification.
  • Other LLRP clients: useful for connection, negotiation and standard inventory tests, subject to each client's implementation.
  • LLRPCSharp: the Reader SDK and Reader CLI can connect directly for software integration tests.
