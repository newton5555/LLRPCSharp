LLRPCSHARP / CLI USER’S GUIDE

Reader CLI User’s Guide

LlrpCli (command name llrp) is built on LlrpSdk for real or virtual reader connections, capability inspection, settings deployment, inventory, standard Tag Access, LLRP hex frames and Wireshark .pcapng capture analysis.

1. Scope and launch

Run the CLI from the source tree:

dotnet run --project src/LlrpCli/LlrpCli.csproj

Release builds are self-contained multi-platform executables. See the release hub for archives. Reader CLI does not create virtual-device servers; use the separate Virtual Device CLI for device-side simulation.

2. Interactive Live Shell

Connect first, then inspect status and capabilities:

> connect 192.168.1.100
> status
> status --full
> caps
> caps --raw
> caps --json
connect <host> [--port 5084]Connect and negotiate the protocol version.
status [--full]Show connection and managed state; --full refreshes Settings, ROSpec and AccessSpec.
caps [--raw|--json]Refresh normalized capabilities; --raw expands protocol data and --json emits script-friendly output.
syncRefresh the observed reader snapshot without clearing SDK DesiredState.

3. Settings and resources

Live Shell does not keep an implicit draft. A write operation requires explicit defaults, a file and confirmation:

> settings apply --defaults --yes
> settings apply settings.json --yes
> settings validate settings.json
> settings show --json
> settings edit
settings apply --defaults --yesBuild and apply a device-aware default baseline.
settings apply <file> --yesValidate and apply local JSON while preserving foreign resources by default.
settings apply <file> --yes --replace-allExplicitly take over and delete all standard resources.
settings validate <file>Read and validate without changing the reader.
settings show [--json|--raw]Read high-level settings and optionally expand raw resource trees.
settings save <file>Save high-level settings for review or later application.
Takeover warning: --replace-all deletes standard resources created by other applications. Prefer the default PreserveForeign policy on shared readers.

4. Inventory and tag operations

> inventory start
> inventory start --monitor frames
> inventory start --monitor live --monitor-duration 30
> inventory status --refresh
> inventory stop

> tag read E28011910000000000000001 --bank user --word 0 --count 2
> tag write E28011910000000000000001 --bank user --word 0 --data CAFEBABE --yes
> tag lock E28011910000000000000001 --target user --privilege lock --yes
> tag kill E28011910000000000000001 --yes

inventory start uses the SDK-managed inventory resource and consumes one report outlet. --monitor frames is useful for raw LLRP observation; --monitor-duration limits foreground monitoring and is not the same as stopping the device-side inventory.

Read, Write, Lock, Kill and Erase use the standard SDK Tag Access path. Kill, Lock and write operations can be irreversible; the CLI requests confirmation and production workflows should restrict both permissions and tag selection.

5. One-shot automation

Use one-shot commands from CI, agents or operations scripts without entering the interactive shell:

# Online status and capability queries
dotnet run --project src/LlrpCli/LlrpCli.csproj -- status 192.168.1.100
dotnet run --project src/LlrpCli/LlrpCli.csproj -- caps 192.168.1.100 --output json

# Connect, deploy, inventory for 10 seconds and emit JSON
dotnet run --project src/LlrpCli/LlrpCli.csproj -- inventory 192.168.1.100 --duration 10 --yes

# Use a local settings file
dotnet run --project src/LlrpCli/LlrpCli.csproj -- inventory 192.168.1.100 --settings reader.json --duration 30 --yes

One-shot commands connect, perform the operation and disconnect. Use Live Shell for long-running observation or step-by-step editing.

6. Offline protocol tools

inspect, decode, validate and encode do not connect to a reader; they process hex frames or pcapng captures:

inspect <HEX>Inspect the LLRP header: version, message type, message ID and length.
decode <HEX|PCAPNG> --output summaryDecode a frame or capture; summary shows direction, message name, ID and length.
validate <HEX>Validate frame length and structural integrity.
encode <MESSAGE> --llrp <VERSION>Build an LLRP hex frame from a message name and options.
# Capture summary
dotnet run --project src/LlrpCli/LlrpCli.csproj -- decode capture.pcapng --output summary

# Full tree or JSON
dotnet run --project src/LlrpCli/LlrpCli.csproj -- decode capture.pcapng --output text
dotnet run --project src/LlrpCli/LlrpCli.csproj -- decode capture.pcapng --output json

# Build a message for an explicit protocol version
dotnet run --project src/LlrpCli/LlrpCli.csproj -- encode get-reader-capabilities --requested-data All --llrp 2.0

Live and offline commands support 1.0.1, 1.1 and 2.0 according to the command path; the offline registry also includes Impinj and Zebra extensions. decode recognizes an existing pcapng file automatically.
