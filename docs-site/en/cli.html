03 / READER CLIENT CLI TOOL

Operations, automation and protocol diagnostics

LlrpCli (llrp) is built on LlrpSdk and LlrpNet.Protocol. It provides a live shell for field work, one-shot commands for scripts and agents, and offline decoding for Wireshark .pcapng captures.

Modes

# Start the interactive shell
dotnet run --project src/LlrpCli

# Run a one-shot inventory command
dotnet run --project src/LlrpCli -- inventory 192.168.1.100 --duration 10 --yes

# Decode an offline capture
dotnet run --project src/LlrpCli -- decode ./capture.pcapng --output summary
Live shell

Maintain a reader connection, inspect status and capabilities, and observe inventory.

Automation

Run non-interactive commands and emit structured output for scripts or development agents.

Offline diagnostics

Inspect, decode, validate and encode LLRP frames without a physical reader.

1. Interactive live shell

> connect 192.168.1.100
> status
> status --full
> caps
> caps --raw

Protocol selection can be made explicitly with the reader connection's --llrp option when the target requires a known version.

2. Settings management

Settings commands use explicit confirmation so field operators do not accidentally replace reader resources.

> settings apply --defaults --yes
> settings apply config.json --yes
> settings apply config.json --yes --replace-all
> settings validate config.json
> settings show --json
ReplaceAll: use it only when the reader is exclusively owned by this process. The default PreserveForeign strategy leaves foreign resources intact.

3. Live inventory

> inventory start
> inventory start --monitor frames
> inventory start --monitor live --monitor-duration 30
> inventory status
> inventory stop

4. C1G2 Tag Access

> tag read E28011910000000000000001 --bank user --word 0 --count 2
> tag write E28011910000000000000001 --bank user --word 0 --data CAFEBABE --yes
> tag lock E28011910000000000000001 --target user --privilege lock --yes
> tag kill E28011910000000000000001 --password 00000000 --yes

5. Automation commands

One-shot inventory output can be consumed by CI or local automation.

dotnet run --project src/LlrpCli -- inventory 192.168.1.100 --duration 10 --yes

{
  "durationSeconds": 10.0,
  "totalTagCount": 42,
  "uniqueTagCount": 3,
  "tags": [{ "epc": "E28011910000000000000001", "antennaId": 1, "readCount": 28, "peakRssi": -52.0 }]
}

6. Offline protocol tools

These operations do not connect to a reader.

CommandInputPurpose
inspect <HEX>Hex frameRead the header, version, type, message ID and length.
decode <HEX_OR_FILE>Hex or PCAPNGDecode the message tree or structured JSON.
validate <HEX>Hex frameValidate length, TL/TLV and nested parameter structure.
encode <MESSAGE>Message and optionsBuild a versioned LLRP frame.

7. Wireshark PCAPNG

When decode receives a .pcapng path, it extracts the TCP stream and reassembles LLRP messages.

dotnet run --project src/LlrpCli -- decode ./reader-traffic.pcapng --output summary
dotnet run --project src/LlrpCli -- decode ./reader-traffic.pcapng --message-type 61 --output text
dotnet run --project src/LlrpCli -- decode ./reader-traffic.pcapng --output json
