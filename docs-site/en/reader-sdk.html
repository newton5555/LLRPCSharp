Reader SDK Programmer’s Guide

LlrpSdk is the application-facing managed LLRP client. It brings TCP sessions, protocol negotiation, reader capabilities, settings, managed inventory and standard C1G2 Tag Access behind the LlrpReader facade, so most applications do not need to construct ROSpec or AccessSpec messages by hand.

1. Install and scope

Add the Reader SDK to an application:

dotnet add package LlrpSdk --version 2.0.3

Impinj and Zebra extensions are separate packages and activate only when the connected identity and protocol version match:

dotnet add package LlrpSdk.Extensions.Impinj --version 2.0.3
dotnet add package LlrpSdk.Extensions.Zebra --version 2.0.3
This guide covers the application-facing Reader SDK. Use the LlrpNet Protocol API for frames, codecs, sessions and generated protocol types, and the Reader SDK API Reference for public signatures and contracts.

2. Connect to a reader

LlrpReaderBuilder configures the endpoint and timeout. The default protocol strategy performs automatic negotiation:

using LlrpSdk;

await using var reader = LlrpReader.CreateBuilder("192.168.1.100")
    .WithPort(5084)
    .WithConnectTimeout(TimeSpan.FromSeconds(5))
    .Build();

await reader.ConnectAsync();
Console.WriteLine(reader.Identity);

After connection, Capabilities, Identity and extension activation have device context.

3. Read reader capabilities

LLRP commonly represents RF mode, transmit power and receive sensitivity as indexes. Read their meanings from the current reader instead of guessing:

ReaderCapabilities capabilities = reader.Capabilities!;

Console.WriteLine(capabilities.MaxAntennas);
foreach (var mode in capabilities.RfModes)
    Console.WriteLine(mode.Description);
foreach (var power in capabilities.TransmitPowerTable)
    Console.WriteLine(power.TransmitPowerDbm / 100.0);

GetDefaultSettingsAsync() creates a recommended baseline from the connected identity, negotiated version and capability tables. It is not a snapshot of the reader’s current configuration; use QuerySettingsAsync() for observed state.

4. Configure the reader

ReaderSettings represents application intent. The usual flow is “get capability-aware defaults → edit → apply”; applying settings leaves inventory stopped until it is explicitly started:

ReaderSettings baseSettings = (await reader.GetDefaultSettingsAsync()).Settings;

ReaderSettings settings = baseSettings.Edit(builder => builder
    .Inventory(inventory => inventory
        .Antennas(1, 2, 3, 4)
        .Mode(modeIndex: 1000)
        .Session(2)
        .Population(128)
        .ReportEveryTag()));

await reader.ApplySettingsAsync(settings);
DEFAULT

PreserveForeign

Replaces only SDK-owned ROSpec, AccessSpec and temporary resources, preserving resources owned by other applications.

EXPLICIT

ReplaceAll

Deletes all standard ROSpec/AccessSpec resources and is appropriate only when the reader is dedicated to this application.

Settings files, SDK defaults and observed reader snapshots are different sources. Raw or expert changes are not silently converted into new application intent.

5. Managed inventory and reports

After applying settings, use an independent InventorySession to consume reports:

await using var session = await reader.StartInventoryAsync();
await foreach (TagReport tag in session.ReadReportsAsync())
{
    Console.WriteLine(tag.EpcHex);
}

InventorySession.ReadReportsAsync(), TagsReported and connection-level ReadTagReportsAsync() are mutually exclusive report outlets. The first consumer in an inventory lifecycle owns the stream.

Recovery boundary: reader ROSpec/AccessSpec resources are commonly volatile. Reconnect synchronizes observed state but does not guess and replay every desired setting; keep your own ReaderSettings or InventorySettings and redeploy when required.

6. Tag Access

The SDK manages the AccessSpec lifecycle for standard C1G2 operations. This minimal example selects an EPC and reads two User-memory words:

var selection = new TagSelection
{
    MemoryBank = TagMemoryBank.ElectronicProductCode,
    BitPointer = 32,
    BitLength = 96,
    Mask = Convert.FromHexString("FFFFFFFFFFFFFFFFFFFFFFFF"),
    Data = Convert.FromHexString("E28011910000000000000001")
};

TagAccessResult result = await reader.ReadTagMemoryAsync(new ReadTagRequest
{
    Selection = selection,
    MemoryBank = TagMemoryBank.User,
    WordPointer = 0,
    WordCount = 2
});

Console.WriteLine(result.Operation.Success);

High-level requests also cover write, lock, kill and block erase. Kill, Lock and write operations can be irreversible; use dedicated tags and an explicit application confirmation path.

7. Vendor extensions

Registering an extension declares a candidate capability. After connection, the SDK activates it only when reader identity and negotiated version match. Check the active extension before using extension settings:

using LlrpSdk.Extensions.Impinj;

await using var reader = LlrpReader.CreateBuilder("192.168.1.100")
    .UseImpinj()
    .Build();

await reader.ConnectAsync();
if (reader.Extensions.Get<ImpinjReaderExtension>() is null)
    throw new NotSupportedException("Impinj extension is not active on this reader.");

The repository provides Impinj and Zebra protocol/SDK extension baselines. Device-model, firmware and field support remain subject to physical interoperability evidence.

8. Lifecycle and boundaries

01Connect, then read Capabilities to generate or validate device-aware settings.
02Applying settings deploys resources; call StartInventoryAsync() explicitly when radio inventory should begin.
03Disconnect, dispose or use await using to finish the Reader lifecycle.
04A compilable LLRP 2.0, Zebra or vendor extension baseline is not a claim that every physical model has been accepted.
