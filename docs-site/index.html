上位机开发

Reader SDK (LlrpSdk)

面向业务应用的高层托管客户端，参考 Octane 理念设计。版本自适应、强类型配置、响应式报告流消费与 C1G2 内存全操作。

  • ReaderSettings 声明式配置与天线功率索引映射
  • InventorySession 流式异步消费与 AttachedData
  • 读/写/锁/灭/块擦除标准 C1G2 Tag Access
  • Impinj / Zebra / Seuic 厂商扩展平滑接入

Device SDK (LlrpDevice.*)

通用的 LLRP 服务端与虚拟读写器仿真核。专为无硬件自动化测试、CI/CD 流水线以及自定义读写器设备固件桥接而设计。

现场运维 & 诊断

Reader CLI (LlrpCli / llrp)

现场工程师的瑞士军刀与 Agent 自动化工具。提供实时交互 Shell、单次 JSON 命令输出以及强大的离线协议分析能力。

  • 交互式 Live Shell：实时滚屏盘点、天线配置与状态同步
  • 自动化命令：单条命令执行盘点并输出结构化 JSON
  • 离线 decode：直接解析 Wireshark .pcapng 抓包
  • inspect / validate / encode 协议报文构造与校验
  • 多版本编解码支持（1.0.1 / 1.1 / 2.0 + Impinj/Zebra）

仿真环境运行

Device CLI (LlrpVirtualDevice.Cli)

独立运行的虚拟读写器服务终端。无需编写任何代码，一行命令启动符合标准的 LLRP 仿真服务，供任意 LLRP 客户端连接联调。

  • 一键启动读写器服务：llrp-device run --port 5084
  • 预设场景库：传送带 (Conveyor)、仓库 (Warehouse)、门禁 (Portal)
  • 交互式 Live 模拟：运行时动态添加/移除标签与故障注入
  • 仿真配置文件 JSON 校验与能力 Profile 查询
  • 完全兼容 Impinj ItemTest、Octane 与第三方 LLRP 客户端

WORKFLOW

标准 SDK 推荐调用顺序

01 ConnectAsync() 建立连接并完成协议版本探查与能力初始化
02 GetDefaultSettingsAsync() 获取适配当前设备物理能力的推荐默认配置
03 ApplySettingsAsync(settings) 部署业务配置并完成资源下发（保持停止状态）
04 StartInventoryAsync() 启动已部署的 ROSpec 并消费异步标签报告流
05 StopAsync() 停止托管盘点并保留当前配置定义

MODERN HERITAGE

从传统 LTK.NET 到现代 LlrpNet 的协议演进

经典 LTK.NET (LLRP Tool Kit for .NET) 开创了由机器可读 XML 规范生成协议强类型模型的工业范式。LlrpNet 完整继承了其严谨的协议定义驱动思想，并基于现代 .NET 10 进行彻底重构：全面升级为 ReadOnlyMemory<byte> 零拷贝内存模型、IAsyncEnumerable<TagReport> 响应式异步流、LLRP 1.0.1 / 1.1 / 2.0 运行时自适应协商，以及 Octane 风格的高层托管意图抽象。

双输入代码生成流水线

兼容官方 LTK XML (llrp-1x0-def.xml) 与现代 YAML 规范，自动编译强类型不可变消息模型与 Codec 注册表。

零拷贝与低内存占用

基于 Span/Memory 与 BinaryPrimitives，在高频标签读写流下大幅降低 GC 压力与内存分配。

纯异步与背压控制

基于 System.Threading.Channels 与 Task 事务匹配，杜绝旧式 APM 模式或线程阻塞导致的死锁风险。

ARCHITECTURAL DESIGN

设计哲学：意图驱动与双轨状态

托管 API 是推荐的默认路径。SDK 使用不可变的 ReaderSettings 记录应用意图，并在后台将其映射为符合当前协议版本的 LLRP 参数。专家资源 API 与 Raw 通道随时开放，但在进行底层写操作后，SDK 会优雅地将观测状态标记为 Stale，并始终保留重构托管资源的能力。
