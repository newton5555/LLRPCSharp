03 / READER CLIENT CLI TOOL

现场运维、自动化脚本与协议分析工具

LlrpCli (llrp) 是基于 LlrpSdk 与 LlrpNet.Protocol 构建的生产级命令行工具。提供用于现场调试的交互式 Live Shell、用于 CI/Agent 调度的单次 JSON 命令，以及可直接解析 Wireshark .pcapng 抓包的离线协议分析核。

工具概览与运行模式

你可以直接在仓库根目录通过 .NET CLI 运行，或将其发布为独立单文件二进制： 

# 启动交互式 Live Shell 终端
dotnet run --project src/LlrpCli

# 执行单次自动化盘点命令（10秒后退出并输出 JSON）
dotnet run --project src/LlrpCli -- inventory 192.168.1.100 --duration 10 --yes

# 离线解析 Wireshark 抓包文件
dotnet run --project src/LlrpCli -- decode ./capture.pcapng --output summary
交互式 Live Shell

现场维护、持续连接读写器、实时观察标签流、动态修改天线参数与状态同步。

Agent 自动化命令

专为本地开发 Agent / 自动化脚本设计，单次执行无交互，直接输出易解析的标准 JSON 数据。

离线协议诊断

不连接物理设备，支持十六进制帧与 .pcapng 抓包的双向编解码与参数树渲染。

1. 交互式 Live Shell 终端

进入 Shell 后，支持连贯的命令操作与实时上下文维持： 

# 1. 连接目标读写器（支持 --llrp auto / 1.0.1 / 1.1）
> connect 192.168.1.100

# 2. 轻量查看当前连接与状态
> status

# 3. 展开完整的 ROSpec / AccessSpec 实况参数树
> status --full

# 4. 查询设备归一化能力表（天线数、功率表、RF Mode 速率表）
> caps

# 5. 额外显示原生 GET_READER_CAPABILITIES 响应报文树
> caps --raw

2. 配置编辑与下发 (Settings)

Live Shell 采用严格的显式确认机制，防止现场误写破坏设备状态： 

# 应用读写器能力的推荐默认配置（部署后保持停止状态）
> settings apply --defaults --yes

# 校验并应用本地配置文件（默认 PreserveForeign 保护外部资源）
> settings apply config.json --yes

# 显式全量接管（清空设备所有外部 ROSpec/AccessSpec）
> settings apply config.json --yes --replace-all

# 仅校验本地文件合法性（零副作用，不向设备写入）
> settings validate config.json

# 从设备重新读取实况并输出为 JSON
> settings show --json

3. 实时标签盘点 (Inventory)

支持 live 汇总与原始 LLRP 帧两种监控模式： 

# 启动盘点并在控制台实时滚动显示刷卡数据
> inventory start

# 实时打印底层接收到的原始 LLRP 数据帧
> inventory start --monitor frames

# 前台监控 30 秒后退出前台（后台盘点保持运行）
> inventory start --monitor live --monitor-duration 30

# 查看盘点运行统计与状态
> inventory status

# 停止盘点
> inventory stop

4. 标签内存读写与锁定 (Tag Access)

# 读取指定 EPC 标签的 User 存储区 (从 Word 0 读取 2 个字)
> tag read E28011910000000000000001 --bank user --word 0 --count 2

# 向 User 存储区写入 16 进制数据 (需要 --yes 确认)
> tag write E28011910000000000000001 --bank user --word 0 --data CAFEBABE --yes

# 锁定 User 存储区为 SecuredWrite (带密码可写)
> tag lock E28011910000000000000001 --target user --privilege lock --yes

# 灭活/销毁目标标签
> tag kill E28011910000000000000001 --password 00000000 --yes

5. 本地开发 Agent 自动化命令

专为本地 AI Coding Agent（如 Antigravity、Claude Code、Cursor 等）或自动化调度脚本设计。以单条命令行参数形式运行，无前台终端交互阻塞，执行后立即输出标准结构化 JSON，便于 Agent 自动解析并开展硬件验收与闭环调试： 

# 连接设备并执行 10 秒自动化盘点，输出结构化 JSON
dotnet run --project src/LlrpCli -- inventory 192.168.1.100 --duration 10 --yes

# JSON 输出示例：
{
  "durationSeconds": 10.0,
  "totalTagCount": 42,
  "uniqueTagCount": 3,
  "tags": [
    {
      "epc": "E28011910000000000000001",
      "antennaId": 1,
      "readCount": 28,
      "peakRssi": -52.0,
      "lastSeen": "2026-08-23T13:20:00Z"
    }
  ]
}

6. 离线协议诊断工具 (Offline Tools)

离线工具无需连接任何读写器，直接对 LLRP 二进制十六进制进行分析或编码：

命令 输入形式 输出与功能
inspect <HEX> 十六进制帧 只读 Header，快速显示协议版本、消息类型、消息 ID 与报文长度
decode <HEX_OR_FILE> 十六进制或 .pcapng 解码消息体，渲染完整参数树或输出结构化 JSON
validate <HEX> 十六进制帧 深度校验报文长度字段、TL/TLV 参数与嵌套结构完整性
encode <MESSAGE> 消息名 + 选项 构造标准的 LLRP 1.0.1 / 1.1 / 2.0 报文十六进制

7. Wireshark .pcapng 抓包解析

decode 命令具备自动识别功能：若传入参数是 .pcapng 文件路径，工具会自动提取 TCP 数据流并重组完整的 LLRP 报文： 

# 1. 摘要模式（推荐：每条报文一行，显示方向徽标与通信对端）
dotnet run --project src/LlrpCli -- decode ./reader-traffic.pcapng --output summary

# 2. 仅过滤 RO_ACCESS_REPORT (MessageType=61) 报文并展开参数树
dotnet run --project src/LlrpCli -- decode ./reader-traffic.pcapng --message-type 61 --output text

# 3. 输出完整会话的结构化 JSON
dotnet run --project src/LlrpCli -- decode ./reader-traffic.pcapng --output json
