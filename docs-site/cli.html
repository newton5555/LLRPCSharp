LLRPCSHARP / COMMAND-LINE INTERFACE MANUAL

LLRPCSharp CLI 命令行工具用户手册

LLRPCSharp 提供两套面向不同场景的工业级命令行工具：面向物理读写器现场运维与抓包分析的 LlrpCli (`llrp`)，以及用于无硬件独立仿真运行的虚拟读写器服务 LlrpVirtualDevice.Cli (`llrp-device`)。

PART 01 / READER CLIENT OPERATIONS & ANALYSIS

一、LlrpCli (`llrp`) 读写器客户端与运维分析手册

LlrpCli 专注于连接真实/虚拟 RFID 读写器进行现场交互式调试、配置下发、C1G2 内存读写、CI 脚本自动化，以及离线解析 Wireshark .pcapng 抓包文件。

1.1 工具概述与启动方式

# 方式 1：通过源码直接启动交互式 Shell
dotnet run --project src/LlrpCli

# 方式 2：发布为单一独立可执行文件 (无需安装 .NET 运行时)
dotnet publish src/LlrpCli -c Release -r win-x64 --self-contained -p:PublishSingleFile=true
./src/LlrpCli/bin/Release/net10.0/win-x64/publish/llrp.exe

1.2 交互式 Live Shell 完整命令指南

直接运行 llrp 进入交互式终端，支持以下完整的命令集：

命令语法功能说明与常用选项
connect <ip> [--port 5084] 连接到指定 IP 的读写器，自动完成协议版本探查与硬件能力查询。
status [--full] 查看当前连接状态、已协商协议版本、以及已下发和期望的配置实况。
caps [--raw] [--json] 查询归一化硬件能力（天线数、发射功率索引表与 RF 模式表）。
settings apply --defaults --yes 基于当前读写器能力表，下发推荐的默认配置基线。
settings apply <file.json> --yes 从本地 JSON 配置文件部署设置（默认 PreserveForeign 保留第三方资源）。
settings apply <file.json> --yes --replace-all 删除读写器上所有既有资源（下发 ID=0 删除命令），独占式部署新配置。
settings show [--json] [--raw] 拉取读写器实况配置并以可读表格或 JSON 格式展示。
inventory start [--monitor live|frames] 启动盘点并在终端实时滚屏显示接收到的标签 EPC、天线与 RSSI。
inventory stop 停止当前正在执行的盘点。
tag read --epc <hex> --bank user --ptr 0 --count 2 按 EPC 匹配标签并读取 User/TID/EPC/Reserved 存储区数据。
tag write --epc <hex> --bank user --ptr 0 --data 12345678 向目标标签存储区写入十六进制字数据。
tag lock --epc <hex> --user-lock SecuredWrite 锁定标签存储区（需提供 Access 密码）。
tag kill --epc <hex> --password <hex> 永久灭活目标标签。
sync 向读写器重新拉取配置实况（更新 ObservedState 状态）。
exit / quit 安全断开连接并退出终端。

1.4 Agent / CI 单次自动化 JSON 调度

在 CI 自动化测试或无人工交互脚本中，可使用单次命令行模式。命令执行完成后以标准 JSON 格式输出，便于程序解析： 

# 自动连接、下发默认配置、盘点 10 秒并输出 JSON 标签数组
llrp inventory 192.168.1.100 --duration 10 --yes

# 校验本地 JSON 配置文件是否符合规范
llrp settings validate ./reader-config.json

1.5 Wireshark 抓包离线深度解析 (`decode`)

无需打开 Wireshark，直接利用 LLRPCSharp 内置的强类型 Codec 引擎对 .pcapng 或 .pcap 文件中的 LLRP 报文进行离线分析： 

# 1. 输出紧凑的 LLRP 会话报文时间线摘要
llrp decode ./capture.pcapng --output summary

# 2. 挂载 Impinj 厂商扩展包，输出完整树状参数明细
llrp decode ./capture.pcapng --extension impinj --output detail

# 3. 将解析结果导出为结构化 JSON 文件
llrp decode ./capture.pcapng --output json > decoded_session.json

1.6 协议 Codec 与帧分析工具 (`inspect` / `encode`)

# 将十六进制原始报文帧反编译为人类可读的参数树
llrp inspect 04030000001000000001000000000000

# 将 JSON 消息定义编译为二进制线协议 Hex 字节流
llrp encode ./get_reader_capabilities.json

PART 02 / STANDALONE VIRTUAL READER SERVER

二、LlrpVirtualDevice.Cli (`llrp-device`) 虚拟读写器服务手册

llrp-device 是一个独立的 LLRP 虚拟读写器服务端程序。无需编写任何 C# 代码，一条命令即可启动一台标准的 LLRP TCP 仿真读写器（默认端口 5084），供任意第三方客户端或自研系统联调对接。

2.1 工具概述与核心运行命令

命令格式说明与示例
llrp-device run [options] 前台服务模式启动读写器（适合容器或后台服务）。
llrp-device run --port 5084 --preset warehouse
llrp-device live [options] 交互式运行模式，终端实时输出 RX/TX 帧级报文跟踪日志。
llrp-device live --port 5084 --preset conveyor
llrp-device presets 列出所有内置的场景预设名称与描述。
llrp-device validate <config.json> 校验自定义仿真场景配置文件的 JSON Schema 与标签格式。

2.3 交互式 Host 管理控制台

直接运行 llrp-device 不带参数即可进入宿主管理控制台：

# 交互式控制台常用命令：
server create --llrp 1.0.1 --port 5084  # 创建读写器实例（未绑定端口）
server start                            # 绑定网络端口并开始接受客户端连接
server status                           # 查看当前运行状态与已连接客户端 IP
server restart                          # 重启 TCP 监听器并断开客户端
server stop                             # 停止服务
caps                                    # 列出当前读写器注册的能力 Profile
logs on / logs off                      # 开启或关闭实时 RX/TX LLRP 报文追踪日志

2.4 场景预设与自定义 JSON 配置文件规范

系统内置了以下常用业务场景预设：

conveyor (传送带场景)

模拟标签以特定速度穿越天线感应区域，产生动态的进入与离开事件。

warehouse (仓库高密度盘点)

模拟 4 根天线覆盖下的上百张高密度标签群，用于压力与吞吐量测试。

portal (通道门禁场景)

模拟双侧门禁天线感应，适用于批量进出库校验。

如需自定义标签数据，可创建 JSON 配置文件并启动：

{
  "profile": "llrp1.0.1_standard",
  "port": 5084,
  "inventory": {
    "tags": [
      {
        "epc": "E28011910000000000000001",
        "antennaId": 1,
        "rssi": -55,
        "tid": "E280110520007001",
        "user": "12345678"
      },
      {
        "epc": "E28011910000000000000002",
        "antennaId": 2,
        "rssi": -62
      }
    ]
  }
}

2.5 第三方客户端联调 (如 Impinj ItemTest)

llrp-device 完全符合 LLRP 1.0.1 / 1.1 国际规范。启动后，可以使用商业上位机软件（如 Impinj ItemTest 2.10.0）直接输入 127.0.0.1:5084 建立连接并执行盘点测试。
